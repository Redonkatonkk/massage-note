# 安全说明

## 已实施控制

- Firebase Phone Auth 验证手机号所有权；密码使用随机盐 `scrypt` 摘要，密码验证成功后由 Admin SDK 签发短期 Custom Token。API 使用 `Secure`、`HttpOnly`、`SameSite=Lax` 会话 Cookie，会话验证包含撤销检查。
- 生产构建硬性关闭本地开发登录。登录使用双提交 CSRF token；其余 Cookie 写请求要求精确匹配受信任 `Origin`。
- 每个业务请求在服务层验证有效店铺成员、角色、对象归属和营业日；跨店隔离、员工财务隔离与角色边界有数据库集成测试。
- 数据库迁移账号与运行账号分离。运行账号不可 DDL，也不能更新/删除审计、AI 查询日志和实时事件。
- 金额使用整数美分和数据库约束；关键写入有事务、乐观锁、幂等键、软删除和同事务审计。
- 登录、加入、AI、导出、SSE 和一般写入使用 Redis 分布式限流；Redis 不可用时安全退化为进程内限流。
- Web/API 返回 CSP、HSTS、frame、MIME、referrer 和 permissions policy；用户文本由 React 按纯文本渲染。
- PWA 只缓存静态壳，不持久缓存已登录业务页。详情草稿最多保留七天；普通退出只清除服务端会话，保留本机 Firebase 登录状态和应用偏好，以便同号码免短信恢复。撤销全部会话仍会使可信状态失效。
- AI 无任意 SQL、URL、文件或财务写工具；参数严格校验，canonical 预览保存在服务器，确认时重新鉴权并原子抢占，一次性消费。
- 语音只在内存中转写，有 8 MB/60 秒上限，不保存原始音频。

## 租户隔离说明

第一版采用“API 服务层强制 `storeId` 作用域 + 对象归属校验 + 非超级用户数据库账号 + 跨店集成测试”。当前没有启用依赖连接会话变量的 PostgreSQL RLS，因为 Prisma 连接池若未把整个请求绑定到同一事务连接，会产生错误隔离语义。若以后引入请求级 Unit of Work，再评估把 RLS 作为第三层纵深防御；在此之前不得用“设置一次连接变量”的不安全方式伪实现 RLS。

## 部署责任

- HTTPS/WAF、主机补丁、Docker 更新、托管数据库 PITR、异地备份、日志留存和告警由部署环境负责。
- Web 与 API 应位于同一 registrable domain 下，且 `WEB_ORIGIN` 必须精确；不要使用通配 Origin。
- PostgreSQL、Redis 和应用内部端口只监听私网/loopback。
- `.env.production` 权限设为 600，不进入镜像、版本库、日志或备份。
- Firebase 测试号码只用于非生产项目；生产启用短信配额、预算与异常告警。
- MiniMax/Google 服务账号使用最小权限并设消费预算；AI 关闭时核心业务仍可用。

## 已知边界

- 这是店铺记工与经营核算工具，不计算工资税、W-2/1099 或报税结果。
- 单机 Docker Compose 不自带 WAF、集中日志或 PostgreSQL 时间点恢复；生产应由反向代理和托管基础设施提供。
- 浏览器 WebM 录音能力在部分 Safari 版本不可用，界面会明确降级到文字输入或系统键盘听写。
- 店内共用设备 PIN 模式不属于第一版。普通退出会保留同号码的本机可信状态，因此共用或公共设备必须使用“撤销全部会话”或浏览器隐私数据清理，不应依赖普通退出实现设备解绑。

发现安全问题时，保留请求编号、时间、账号角色和复现步骤，避免复制真实客户/员工数据或任何密钥。
