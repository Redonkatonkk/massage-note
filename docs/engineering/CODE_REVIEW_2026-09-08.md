## 数据迁移与上线边界

- 当前工作区包含原有 `20260908010000_work_bot_instructions` 和新增 `20260908020000_repair_work_record_board_links` 两个前向迁移。新增迁移仅补看板关联并清理失效机器人占用，不改付款或财务快照。
- 新迁移已在测试库执行；补行 SQL 另用隔离的临时表验证连续执行两次、保留隐藏行与原顺序、不重复增加版本。
- 发布前仍按发布清单在生产数据副本验证迁移耗时和锁影响。历史记录很多时，扫描和写入范围需要用实际数据量评估。
- 没有执行生产部署、推送代码或重启已安装的 Mac 代理。真实 Firebase 短信、MiniMax、微信群回调、macOS 信息送达以及 NAS 镜像部署仍需对应环境验收；本轮未把这些外部链路标记为已验证。
- Messages 没有端到端幂等接口，进程在发送接受与确认记录之间崩溃仍存在不确定窗口。当前策略在已知不确定错误时停止自动换通道重发，保留人工核查路径。

业务/API、机器人、Mac 代理和版本文档已同步。后续维护以对应模块测试、共享契约和数据库约束为准。
