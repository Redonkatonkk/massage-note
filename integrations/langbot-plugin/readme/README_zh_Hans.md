# LangBot 记工机器人

插件版本 1.1.1，要求后端至少 1.1.0（协议 2）：群内 @ 机器人后，每条消息结合店铺实时目录和自然语言说明交给模型理解。最终写入、权限和查询由 Massage Note 后端执行，数据库是金额的唯一来源。

店铺说明可约定“姓名 大费 小费”表示下工并默认信用卡。例如约定后，`Jessica 75 5` 表示给 Jessica 的唯一待付款记录收取服务费 75、小费 5；`Jessica 90 0` 按实际数字理解，`Jessica 75 5 现金` 则优先采用现金。没有默认约定时不会猜付款方式。下工会保留指定员工姓名，并查找网页手动开始或机器人开始的待付款记录；多条待付款记录仍需指定编号。

## 记工与查询

| 示例 | 行为 |
| --- | --- |
| `绑定店铺 123456`、`绑定 Lily` | 绑定群和微信身份；姓名认领本身不授予历史财务访问 |
| `Lily 大力 60` | 给同店 Lily 上工，使用目录价格和提成 |
| `Lily 下了，收 75/15卡，评论` | 实收服务费 $75、刷卡小费 $15、添加配置的评论折扣；保留项目原价 |
| `Lily 加热石`、`Lily 加评论折扣` | 给唯一的待付款记录添加配置项目，重复添加同一预设项不叠加 |
| `Lily 移除热石`、`Lily 取消评论折扣` | 移除已有加项或折扣，停用目录项仍可按快照名称移除 |
| `Lily 高亮`、`Lily 取消高亮` | 设置或取消高亮；影响网页原有刷卡手续费规则 |
| `最近 15 天的折后大费都是多少？给我列表` | 以店铺营业日查询，含当前营业日，默认已付款记录，逐笔列表与全范围合计 |
| `最近 15 天折后大费按天汇总` | 按营业日汇总；也可按员工汇总 |
| `查询 Lily 最近 15 天折后大费，第 2 页` | 员工筛选及分页；每页 20 条，不静默截断 |
| `查询今天待付款记工`、`查询最近 15 天高亮记录` | 按付款状态、高亮筛选；可查询已删除记录以取得恢复编号 |
| `高亮 <完整记录编号>` | 精确操作指定记录，包括已付款记工 |
| `修改 <完整记录编号> 原价 90，现金大费 30，卡大费 60，卡小费 10` | 原子修改项目原价及混合付款；礼物卡付款须明确序列号 |
| `删除 <完整记录编号>`、`恢复 <完整记录编号>` | 软删除或恢复；日结锁与历史权限继续生效 |

“折后大费”是主要项目加加项再减折扣，和实际收到的服务费分别展示。折扣不减少员工的大费工资。未知配置、多个待付款记录或缺少关键信息时不猜记录；可先查列表获得完整编号。

按编号编辑还支持员工、项目、时长、备注、自动折扣开关、手工结清标记、自定义折扣/加项及提成。自定义金额须在消息中明确提供；完整加项/折扣列表的修改会替换原列表，单项添加或移除使用上述简单命令。开始/结束时间修改、历史补录要求明确带时区的 ISO 时间，例如 `2026-09-08T14:00:00-04:00`。补录可指定预设项目或提供完整自定义项目名称、时长和金额。只支持现有网页的业务能力，不支持任意 SQL 或绕过日结。

查询最多覆盖 366 个营业日期。普通员工只能查询本人历史财务，经理和店主可查询全店。分页回复中的总计始终覆盖完整筛选范围；长页拆成多条微信回复。翻页需重复查询范围并注明页码。

## 核实身份并开启数据访问

1. 在群内完成绑定。
2. 店主或经理登录网页 → 店铺管理 → 记工机器人 → 微信群绑定，核对微信 senderId 与员工本人。
3. 点击「核实身份并开启数据访问」。查询结果会发送到该微信群。

核实前只允许普通员工级别的当日记工，不能因为认领经理姓名而获得历史编辑和财务查询权限。核实后仍以成员当前角色为准；未参与服务的经理或店主也能绑定和查账。切换绑定身份取消核实，关闭数据访问后重放旧查询也会重新鉴权。

## 组件与接口

- 插件：`integrations/langbot-plugin`，事件组件 `components/events/work_bot.py`。
- 契约：`packages/contracts/src/work-bot.ts`。限定意图为 BIND_STORE、BIND_MEMBER、START、FINISH、ADJUST、QUERY、MANAGE、HELP。
- 后端：`apps/api/src/work-bot`。复杂写入使用内部绑定身份适配器，复用 `WorkRecordsService`；微信来源与成员身份另有审计记录。
- 管理 UI：`apps/web/app/manage/work-bot-panel.tsx`。
- `POST /api/v1/integrations/langbot/work-context`：返回 `protocolVersion: 2`、店铺营业日期/时区、说明、实时目录、员工和意图 JSON Schema。模型不持有数据库连接信息。
- `POST /api/v1/integrations/langbot/work-events`：验证集成令牌及 `Idempotency-Key: wechatpad:<bot-id>:<message-id>`，执行结构化查询或记工。重复写消息返回原结果；同编号不同内容拒绝。
- `PATCH /api/v1/stores/:storeId/work-bot/members/:bindingId/verification`：已登录管理者提交 `{version, verified}`，核实或撤销微信身份，带版本校验及审计。

## 部署

先部署 Massage Note API/网页 1.1.0，执行迁移：

- `20260908190000_work_bot_verified_access`：新增可空核实时间，既有绑定不自动获得历史权限。
- `20260908190100_work_bot_query_reply`：回复字段扩为 TEXT，支持分页列表。

再构建并通过 LangBot 本地插件安装接口安装 1.1.4。配置保留 `api_base_url`、`integration_token`、`bot`、`model`。令牌必须在插件配置中填写，隔离运行时不会继承容器自定义环境变量；不要放进插件包或 Git。API 必须为最终 HTTPS 地址，本地例外仅 `host.docker.internal`，携带令牌的请求不跟随重定向。

保持记工流水线仅由被 @ 的群消息触发，专用机器人和插件配置不变。新版插件检查后端协议，避免误连旧版 API。安装后核对 `mounted`、`initialized` 日志，并在管理页开启需要查账的真实微信身份。

验证覆盖金额与付款口径、权限与撤销、营业日和夏令时、分页、折扣/加项、高亮、原子混合付款、失败回滚、软删除恢复、重复事件和并发上工。

高亮操作可直接说 `高亮`、`取消高亮`（使用发送者绑定员工），或 `Lily 高亮`、`Lily 取消高亮`。`去掉高亮`、`移除高亮`、`关闭高亮`、`不高亮`、`unhighlight` 均表示取消。已付款记录请用完整记录编号；无编号只操作唯一待付款记录。下工时也可附带高亮/取消高亮。模型必须保留否定词；疑问或“不要取消高亮”等歧义表达不写账。更新需同时部署 API 并安装插件 1.1.4。

## 店铺默认时长与解析失败

API 1.3.7 / 插件 1.1.4：店铺说明约定“大力指 Deep Tissue Massage；未提时长默认60分钟”时，`@Jeunesse jessica 上工 大力` 应映射至目录中的对应项目、Jessica 和60分钟。默认时长使用 `durationSource=SKILL`，不编造原文时长证据；显式时长优先。员工、项目和价格档仍须存在于当前店铺。后端保留 @ 员工的姓名证据。

每条消息仍读取当前店铺说明。第一次解析为 HELP 且店铺有说明，或结构不合格时，插件最多复核一次；复核仍有歧义则保持 HELP。两次结构不合格明确报错；后端原文证据不匹配返回 `INTENT_EVIDENCE_REJECTED`，说明本次没有记账。复核最多增加一次模型调用。需更新 NAS API 并重新安装插件 1.1.4 才生效。
