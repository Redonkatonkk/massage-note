# Massage Note 记工助手

当前插件 **1.4.1**；完整能力要求 API **至少 1.7.0**、协议版本 2。版本以 `manifest.yaml` 为准。

群内 @ 专用机器人后，插件读取实时目录及说明，交给模型理解，再向 API 提交受限意图。支持绑定、上工、下工、折扣/加项/高亮、历史查询、按编号编辑与软删除恢复，以及 2–10 位员工的原子批量操作；歧义在插件内澄清。

## 配置与保留规则

- 在 LangBot 配置 `api_base_url`、`integration_token`、`bot`、`model`，使用最终 HTTPS 地址，本地 HTTP 例外仅 `host.docker.internal`。保留原因：隔离进程依赖插件配置，携带令牌的请求不跟随重定向。
- 流水线只允许被 @ 的专用机器人群消息进入。保留原因：事件监听器会接管所有已路由给它的消息。
- 店主或经理先核实微信身份，再开启历史访问。保留原因：绑定姓名不能证明身份，查询结果会回复到请求群。
- 金额、权限、幂等和数据库查询由后端执行；本次原文、实时目录与明确店铺说明优先。保留原因：模型和学习经验不能授予权限、虚构金额或授权默认付款/时长。
- 最近对话只用于理解：同一范围最多 5 轮，空闲 30 分钟失效，重启清空；最多 256 个会话，超过 4,000 字符的整轮跳过。保留原因：限制内存和历史干扰，避免把过去的记工当成新指令。
- 澄清需在 30 分钟内确认；确认只保存经验，业务操作另发完整指令。保留原因：学习确认不是记账授权，纠正中的旧经验会先停用。
- 学习存储和备份按运行数据保护。保留原因：其中含消息片段，按配置、店铺、机器人、群、发送者及绑定姓名隔离，每范围保存 50 条经验、30 条未理解事件和 30 条回复回执，跨重启保留；存储失败不能声称已记住。
- 先升级所需 API/迁移，再构建安装插件并核对 `mounted`、`initialized`；令牌不进安装包，不以复制运行目录替代安装。保留原因：本地源码不代表运行版本，安装包必须可追溯且不含凭据。

## 使用举例

| 消息 | 行为 |
| --- | --- |
| `绑定店铺 123456`、`绑定 Lily` | 绑定群和微信身份 |
| `Lily 大力 60` | 使用店铺目录上工 |
| `Jessica 75 5` | 仅在店铺已约定该下工格式与付款方式时使用 |
| `Lily 加热石`、`Lily 取消高亮` | 修改唯一待付款记录 |
| `查询 Lily 最近 15 天折后大费，第 2 页` | 按范围分页，合计覆盖完整范围 |
| `Ling Jessie 上工 大力` | 两人上工，全部通过校验才一起提交 |
| `删除 <完整记录编号>`、`恢复 <完整记录编号>` | 按权限软删除与恢复 |

完整业务与运维说明在仓库 `docs/operations/LANGBOT_WORK_BOT.md`，开发、验证及打包见源码目录 `DEVELOPMENT.md`。本文随插件包分发，只保留安装所需规则和示例。
